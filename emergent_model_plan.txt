Emergent model integration plan (draft)
=======================================

Context
-------
The current main program (automaton3d/automaton) still initializes pB, sB and phiB
statically, while two separate prototypes have shown how these patterns can be
made emergent and dynamical. This draft proposes how those prototypes could be
unified into the main model. It is intended as a working document for review,
not as a final manuscript text.


1. Cloud: from static sin^2 to emergent sin(r)/r (or r*sin(r))
-------------------------------------------------------------
Prototype: automaton3d/sine2 (mytry.c, ca_cuda.cu, pulsating.h)

Old model:
- phiB is a bit mask computed once at initialization from sin^2(r) and a RNG.
- It is distributed isotropically on the sphere and then used as a sieve.

New prototype:
- No phiB at init. Instead the lattice carries a 3-D integer wave field (u =
  displacement, v = velocity) and a Bresenham accumulator acc.
- A pulsating spherical wavefront expands from the center by BFS, computing r
  (integer radius) and r^2 dynamically. The active shell is the coincidence
  between the wavefront and the wave field.
- The wave equation evolves with integer-only arithmetic (add, sub, shift).
  Shell forcing drives u toward SHELL_TARGET near r = SHELL_R; boundary
  absorption truncates the wave near the grid edge.
- After a transient, the radial profile of u stabilizes into a damped
  oscillation that approximates sin(r)/r. At that moment each cell gets a pair
  (sinc_p, sinc_q) = (u, peak) that acts as a Bresenham rational for triggering.
- The old phiB sieve is therefore replaced by an emergent, continuously
  regenerated trigger condition based on the local wave amplitude and the
  Bresenham ratio sinc_p/sinc_q.

Open point (A): the user wrote "r*sin(r)" while the prototype header says
"sin(r)/r". Need to confirm which functional form is the target. The code
produces sin(r)/r; if the intended cloud is r*sin(r), the shell forcing and
normalization would need to be changed (e.g. no 1/r damping near the origin).

Open point (B): rotation of the cloud. In the old model phiB is isotropic, so
no rotation is needed. In the emergent model the wave is centered at the
origin. If the bubble itself moves/rotates, the cloud must be rotated with it.
The rotation prototype (automaton3d/rotation) can rotate an arbitrary 3-D
configuration of active cells; it remains to decide whether the wave field is
rotated as a passive object (rotate the u/v values along with the lattice) or
whether the cloud is re-emitted in a new direction after each reissue.


2. pB/sB -> M/S as emergent rotation patterns
---------------------------------------------
Prototype: automaton3d/rotation (ac_rotation.c, pure_ca_rotation.c,
manuscript_rotation.tex)

Old model:
- pB is a bit that marks a privileged direction (linear motion).
- sB is a bit that marks a spiral around the pB axis.
- Both are distributed isotropically over all layers at initialization.

New prototype:
- A 3-D rotation is performed by decomposing it into three axis-aligned shears
  (Paeth decomposition). Each shear is realized by shifting rows/columns by an
  integer number of cells, where the shift is computed by a Bresenham
  accumulator from a rational pair (p,q):
        sin(theta) = p/q
  This gives an exact, bijective, integer-only rotation of any set of active
  cells. Convergence to the ideal rotation is achieved by scaling the pair by L.
- The same machinery can be used to rotate the cloud of Section 1, giving a
  dynamically chosen direction.

Proposed reinterpretation for pB/sB -> M/S:
- M (momentum) is the emergent linear direction. It is not a single bit but a
  rational pair (p_M, q_M) together with an axis of rotation (the line along
  which the bubble is currently moving). Operationally it is the Bresenham
  direction that the bubble follows when it is reissued after an interaction.
- S (spin) is the emergent spiral/rotation around the momentum axis. It can be
  encoded by a second rational pair (p_S, q_S) that drives the Paeth rotation
  of the cloud/particle. The sB spiral is no longer a precomputed path but the
  sequence of active cells produced by successive applications of the rotation.
- Isotropy is not assumed at init. Instead, every possible (p,q) pair can be
  generated by repeated local interactions (scattering, pair formation, reissue),
  so the population of M/S directions becomes statistically isotropic after many
  iterations.

Open point (C): how many bits/rationals per cell? In the old model pB and sB
are single bits. In the emergent model a direction needs at least a pair (p,q)
(and possibly an axis/phase). The cell structure would need new fields: e.g.

    int m_p, m_q;    // Bresenham ratio for linear motion
    int s_p, s_q;    // Bresenham ratio for spin/rotation
    uint8_t phase;   // which step of the Paeth shear is currently active

or, alternatively, the pair can be stored in W as part of the internal
dimension (extending the W-island identity by a direction register).


3. Integration with the main automaton model
--------------------------------------------
The main program (automaton/src/model/initSim.cpp and simulation.h) currently
has a Cell with:
    uint8_t ch (6 charge bits)
    bool pB, sB, phiB, etc.
    uint32_t a, t, k, ...

To integrate the emergent mechanisms, the static pB/sB/phiB fields should be
replaced or augmented by:

    Wave/cloud fields (from sine2):
        int u, v;            // wave displacement and velocity
        int acc;             // Bresenham accumulator
        int sinc_p, sinc_q;  // emergent trigger ratio
        unsigned r;          // dynamic integer radius
        unsigned r2;         // squared distance (INF_R2 if unvisited)
        unsigned active;     // coincidence with pulsating shell

    Rotation/motion fields (from rotation):
        int mp, mq;          // momentum rational (replaces pB)
        int sp, sq;          // spin rational (replaces sB)
        uint8_t rot_phase;   // phase in Paeth 3-shear cycle
        int target_disp;     // remaining displacement in current shear

The pulsating wavefront, the sinc wave, and the rotation would then be part of
the light-frame cycle, not initialization:

    1. PULSE step: expand the r^2 wavefront by BFS (one light step).
    2. SINC step: update u/v/acc and compute the emergent sinc_p/sinc_q.
    3. INTERACTION step: when the active shell of a bubble touches another
       bubble, perform the appropriate reissue/annihilation/pairing and set
       the new momentum rational (mp,mq) and spin rational (sp,sq).
    4. ROTATION step: apply one Paeth shear step to rotate the cloud/particle
       around the axis defined by S, preparing the next light step.

This effectively makes the "frame" longer: each light step would contain a
pulsation sub-cycle, a wave sub-cycle, and a rotation sub-cycle. The key point
is that all of these are local, integer-only operations compatible with the FSM
design.


4. Connection with W-islands, K/D/S and charge quantization
------------------------------------------------------------
- W-islands provide the charge template (9L families, L/3 identical copies).
- K/D/S provide the particle structure (1K + nD, free S).
- The emergent M/S and cloud provide the motion and wavefront of each copy,
  not its charge identity. Two copies from the same W-island can have the
  same charge but different M/S states, until interactions equalize them.
- Pair formation and reissue now also exchange or average the (mp,mq) and
  (sp,sq) rationals between bubbles, similar to how the old model exchanges
  pB/sB bits. The convolution step in W continues to equalize the charge
  identity of merged islands.
- The dynamic charge quantization hypothesis (capture vs. escape rates) is
  unchanged; it only describes how many S copies are bound to a K. The emergent
  wave/rotation mechanisms provide the transport that lets copies meet and
  be captured.


5. Main open questions to resolve before updating the manuscript
---------------------------------------------------------------
A. Functional form of the cloud: sin(r)/r or r*sin(r)?
B. Cloud rotation: passive rotation of the u/v field or re-emission in the
   new direction at each reissue?
C. M/S representation: separate rationals per cell or encoded in W?
D. Time schedule: how are the pulse, sinc, interaction, and rotation steps
   interleaved in the light frame?
E. Integration test: should we first write a minimal combined CA that has
   wave + rotation + one K/S before attempting the full automaton?
